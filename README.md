# 上市公司运营模式与风险研判

一个用于Claude Code 等 Agent 环境的技能（Skill），对上市公司作模式层面的风险研判，并产出含图表的单文件 HTML 研究报告。

它回答的是一个可检验的命题：**一家公司既有的经营模式，其抗风险能力是结构性的，还是阶段性的。**

这个区分决定投资判断的走向。结构性能力源于企业自身的制度安排，在下一周期仍可沿用；阶段性能力只在一段特定的外部窗口内有效，窗口条件改变即失效。两类能力的当期财务表现可能完全一致，但含义相反。

> A skill for judging the risk profile of a listed company's business model, and producing a self-contained HTML research report with charts.

## 它解决什么问题

拿到一家公司的财报，最常见的两种误判是：

**把问题全推给外部。** 认为政策放松或行业回暖就能恢复，没有检验公司自身的应对能力，也说不清为什么同一环境下的可比公司表现不同。

**直接断言模式失效。** 说得出"这家公司不行了"，却指不出失效的具体环节，把经营结果的恶化等同于模式失效。

这个技能的作用是让判断落在这两者之间。它不预设结论，而是通过固定的追问顺序，把判断定位到具体情形上。

## 核心方法：三步追问法

追问顺序不可调换，每一步的结论构成下一步的前提。在进入这三步之前，先建立行业层面的参照。

### 前置：先建立行业参照

战略分析的标准顺序是行业、公司、判断。跳过行业直接分析公司，会导致三处落空：无法说明公司当前的利润率水平从何而来、无法判断外部压力属行业性还是个体性、无法判断转型的时间窗口是否存在。

行业层面覆盖五个方面：市场容量与增速、行业盈利水平与集中度、成本与技术特征、规模经济与范围经济、纵向整合与客户结构。取不到数据的维度须在报告的"分析覆盖范围"表中如实声明，不得沉默跳过。

### 第一步：收入来源

落到具体的收入构成，不停在"卖设备""做服务"这一层。找出底盘在哪：哪块业务体量大、黏性高、现金流稳。

设备与耗材的绑定是典型判断点。设备是一次性交易，耗材随装机量持续复购且切换成本高，后者才是底盘。

### 第二步：风险敞口

定位底盘最敏感的外部变量。敞口分布在三个端口：

| 端口 | 含义 | 典型变化 |
|---|---|---|
| 支付端 | 资金支付方及其规则 | 支付方式改革、集中带量采购、补贴退坡 |
| 采购端 | 采购决策方及其程序 | 招投标规则调整、国产替代政策、基建节奏 |
| 结算端 | 交易计价与结算币种 | 汇率波动、结算方式变更 |

结算端是出口导向型企业必查项。然后做同群对照，判断压力属行业共同还是仅针对这家公司。

### 第三步：可转换性

依次回答三个问题：有没有第二条路；第二条路的体量够不够补上主业缺口；转过去要付出什么代价。

| 情形 | 结论 |
|---|---|
| 换不动 | 结构性风险，环境改善无法解决 |
| 换得动但慢 | 过渡期风险，要看现金流能否撑过这个阶段 |
| 换得动 | 阶段性困难，外部条件恢复后经营可随之恢复 |

## 产出效果

交付物是单文件 HTML，样式内联，不依赖外部资源，双击即可打开，也支持打印。

正文含不少于四张图表，分别承载四类判断，不是随意配图：

| 图 | 承载的判断 | 图形 |
|---|---|---|
| 图 1 | 收入构成与底盘所在 | 环形图 / 堆叠条形图 |
| 图 2 | 外部压力的时间轨迹 | 折线图 |
| 图 3 | 压力属行业性还是个体性 | 分组柱状图（公司与可比公司并列） |
| 图 4 | 替代路径能否补足主业缺口 | 对照条形图 / 瀑布图 |

每张图下方强制三行标注：标题、数据来源、读图要点。第三行是硬要求，缺了图表就接不上分析。

涨跌配色遵循 A 股惯例，涨红跌绿。柱状图的正负以方向区分，零线以上为增长、以下为下降，柱长与数值严格成比例，不靠颜色单独区分正负。

报告在交付前须通过四项自检：正文无残留的 Markdown 语法、柱长与数值成比例、SVG 文字坐标不越界、含窄屏响应式规则。这几项都不会报错，只会直接印在页面上，因此列为必检。

示例中的判断与结论仅作方法演示，不构成任何投资依据。

## 交互方式

技能分两层互动：分析过程中的对话，以及报告本身的交互元素。

### 对话互动

**边界是互动只作用于事实与范围，不作用于方法判断。** 可以决定分析哪家公司、同群对照选谁、分析到哪个层面、数据截止到哪一期；不能决定三步追问的答案。

开工前确认三项，一次问完：分析范围、数据截止期、可比公司。三项都已交代清楚时跳过，缺省倾向于不问。执行中只在两种情况停下来：数据不足以支撑核心结论，或检索到与前提相矛盾的事实。

交付后给出两到三个有实质内容的追问方向，并询问是否建立跨报告期跟踪。

**不因坚持而改结论，结论只能因新证据而改。** 对结论提出异议时，技能会先问依据：依据若是可核的数据或事实，纳入重新判断；依据若是主观判断或立场，说明这不构成对方法的修正，并指出该判断在什么条件下成立。

### 报告交互元素

四个：结论卡可展开看依据、数据来源表可按层级与核实状态筛选、图表数值可悬停查看精确值、多指标对照图可切换口径。

**渐进增强是硬要求**，关闭脚本后报告内容仍完整可读，打印预览中也不会因折叠或筛选而缺内容。

### 跨报告期跟踪

分析完成后可建立跟踪。下次定期报告披露时运行，产出的是更新说明而非重跑整份报告：列新报告期数据、各观察点的变化方向、核心判断是否需调整及依据。判断若发生变化，须说明变化来自新证据而非数据波动。

## 数据来源规范

这是本技能与一般"让 AI 写研报"区别最大的部分。`references/source-policy.md` 把来源分三级，判级标准是两个问题：**发布主体是谁，能不能拿到可下载的原件。** 答不出主体或拿不到原件，最高只能算三级。

| 层级 | 范围 | 使用方式 |
|---|---|---|
| 一级·原始披露 | 公司定期报告与法定公告、监管与政府部门文件、官方统计 | 可直接引为论据 |
| 二级·可核来源 | 行业协会统计、公开招投标数据、证券研究报告、专业数据库 | 涉及财务数据须与一级来源交叉核对 |
| 三级·线索性来源 | 媒体报道、自媒体、社交平台、百科 | 仅用于发现线索，不得作为论据 |

同时明令禁止：无署名网络文章、算法生成的信息聚合页、荐股群与直播的"内部消息"、未核实传闻、篡改拼接内容、引流软文。

两条硬规则：

- **正文不得出现无来源的数字。** 确需定性判断而无数据时，改为不使用数字的表述。
- **媒体的分析性判断同样不得引用。** 分析结论须依据原始数据自行推导。

每条数据在来源表中登记七个字段：数据项、数值/口径、来源层级、来源名称、日期、定位、状态。

## 适用与不适用

**适用**：模式层面的风险研判、竞争优势可持续性评估、个股研究报告。

**不适用**：短线技术分析、纯估值建模（现金流折现、相对估值测算）、行业整体比较研究。
