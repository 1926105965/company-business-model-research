# 分行业补充模块

本目录存放按行业分类的补充规则。当分析对象属于下列行业时，除执行 SKILL.md 的主框架外，还须加载对应的行业补充模块。

## 模块与主框架的关系

主框架的三步追问法（收入来源、风险敞口、可转换性）在各行业仍然适用，但每一步的**操作细则**与**判断标准**按行业模块调整。行业模块未覆盖的维度，回退到主框架的通用规则。行业模块与主框架冲突时，以行业模块为准，理由是行业特殊性优先于通用规则。

主框架中有一类内容不受行业模块影响，任何行业都须遵守：来源分级与七字段标注、正文不得出现无来源的数字、同群对照不可省略、风险提示不可省略、外部观点辑录的隔离要求。

## 现有模块

| 行业 | 文件 | 适用标的特征 |
|---|---|---|
| 银行 | `banking.md` | 收入主要来自利息净收入、手续费及佣金 |
| 保险 | `insurance.md` | 收入主要来自保费收入、投资收益 |
| 房地产 | `real-estate.md` | 收入来自物业销售、租金、物业管理 |
| 互联网平台 | `platform.md` | 收入来自广告、交易佣金、增值服务、订阅 |
| 公用事业 | `utility.md` | 收入受政府定价约束，具备自然垄断或特许经营特征 |
| 医药 | `pharma.md` | 收入来自药品销售，核心变量为医保支付、集采、研发管线 |
| 半导体 | `semiconductor.md` | 收入来自芯片设计、制造、封测，核心变量为技术节点与产能周期 |

## 七份模块的成熟度不同，使用时须分别看待

银行与互联网平台两份在真实案例上跑过，其余五份系按行业通用知识编写，**尚未经真实案例验证**，使用中若发现与实际情况不符，以实际数据为准并回报差异。这一条不是免责声明，而是使用前提：未经验证的模块给出的是待检验的假设，不是既定结论。

各模块中所有量化阈值同理，均为未经实证校准的参考起点，校准方式见 `../backtest-guide.md`。

## 如何判断使用哪个模块

根据公司年报"主营业务"描述与收入构成判断。一家公司可能同时适用多个模块（如"医药＋互联网平台"的在线医疗），此时取收入占比最高的业务对应的模块为主，另一模块为辅，并在报告中说明两个模块分别覆盖了哪些维度。

判断依据须写明：是依据收入构成，还是依据年报的业务描述。若两者不一致（年报描述为主业但实际收入来自另一业务），以收入构成为准并在报告中说明差异。

## 新增模块的规范

新增行业模块须包含下列章节，缺一不可：

1. **准入筛查调整**：该行业特有的不适用情形
2. **第一步调整**：该行业如何识别底盘，替代通用的"设备与耗材绑定"判断点
3. **第二步调整**：该行业特有的风险端口，替代或补充支付端、采购端、结算端
4. **第三步调整**：该行业如何判断可转换性，替代通用的三档判断
5. **行业特有指标**：必须采集的行业专属数据项，含计算方式与来源
6. **同群对照调整**：该行业选取可比公司的特殊标准
7. **常见陷阱**：该行业特有的分析误区

另须在文件开头标注该模块是否已由真实案例验证。未验证的按上一节的要求声明。
