# 可视化规范

研报交付形态为单文件 HTML 页面，其中须含四至七张图表。规范规定页面结构、图表类型与数据的映射规则、配色与标注要求。

## 页面结构

单文件 HTML，所有样式与脚本内联，不依赖外部资源，双击即可在浏览器中打开。页面自上而下分五个区块。

| 区块 | 内容 | 图表 |
|---|---|---|
| 报告头 | 公司名称、股票代码、报告日期、数据截止期、分析框架 | 无 |
| 核心结论 | 三到五句判断，以结论卡形式呈现，分层判断用两块并列 | 可选一张估值或经营概览图 |
| 分节正文 | 按研报模板的各章节展开，每节承载其核心图表 | 四至七张 |
| 观察点 | 该盯什么、不该盯什么，表格形式 | 可含一张趋势图 |
| 数据来源 | 来源追溯表，含层级、来源名称、日期、定位、状态 | 无 |

页面顶部设固定导航条，点击跳转至各节。页面宽度控制在 1100 像素以内的居中栏，正文行高不低于 1.7，确保长文可读。

## 图表数量与类型映射

正文须含四至七张图表，覆盖下列核心判断。图表类型按数据关系选定，不按美观偏好选定。

| 数据关系 | 图表类型 | 用于呈现 |
|---|---|---|
| 收入的构成与占比 | 环形图或堆叠条形图 | 各业务板块占比、境内外收入结构 |
| 变化的方向与幅度 | 分组柱状图 | 营收与净利的同比，公司自身跨期对照 |
| 同业同期的横向比较 | 分组柱状图或斜率图 | 公司与可比公司的营收、净利同比对照 |
| 时间序列的趋势 | 折线图 | 毛利率、净利率、汇兑损益的逐期变化 |
| 结构差异与缺口 | 瀑布图或对照条形图 | 主业缺口的绝对金额与新业务体量的对比 |
| 多指标的相对位置 | 雷达图或热力表 | 公司与同业在盈利能力、成长性、现金流上的分布 |
| 目标与现状的距离 | 进度条形图 | 市占率目标与当前水平的差距 |

**硬性要求**：

- 同业对照须单独成图，不得只在文字中表述。这是全文归因的基础，图形化后差异一目了然。
- 至少有一张图呈现时间序列，用于说明趋势而非单点。
- 至少有一张图呈现公司与同业的并列，用于区分行业性问题与个体问题。
- 饼图仅用于部分与整体的关系，且分块不超过五块。
- **图表总数为四至七张。**

上限的理由是取舍。四张对应四类核心判断，加行业环境一张为五张，剩余两张用于估值、目标进度或同业多指标分布这类可选内容。**同一结论不得重复作图**，例如同一组数据既画柱状图又画折线图属于凑数。超过七张说明制图时未作取舍，读者的注意力会被摊薄，重点图反而失去分量。

## 配色规则

页面采用浅色底、深色字，保证打印与投影均可读。主色为靛蓝色系，全报告不超过两个主色，其余用中性灰。

### 主色板（分类数据：收入构成、业务分组）

从深到浅，表示从主要到次要：

| 色号 | HEX | 用途 |
|---|---|---|
| 主色 1 | #6366f1 | 主要类别 / 第一大项 |
| 主色 2 | #818cf8 | 第二大项 |
| 主色 3 | #a5b4fc | 第三大项 |
| 主色 4 | #c7d2fe | 第四大项 |
| 主色 5 | #e0e7ff | 第五大项 / 其他 |

### 语义色（涨跌、正负方向）

涨跌配色遵循 A 股惯例：

| 色号 | HEX | 用途 |
|---|---|---|
| 涨 / 正 | #ef4444 | 增长、正值（A 股惯例：涨红） |
| 跌 / 负 | #22c55e | 下降、负值（A 股惯例：跌绿） |
| 中性 | #94a3b8 | 零值、持平 |

配色方案相反的情形（如欧美市场惯例的红跌绿涨）不适用于本技能。所有图表与表格中的涨跌标注须保持一致。

### 对比色（同群对照图）

| 色号 | HEX | 用途 |
|---|---|---|
| 目标公司 | #6366f1 | 分析对象 |
| 可比公司 A | #818cf8 | 第一家可比公司 |
| 可比公司 B | #a5b4fc | 第二家可比公司 |

目标公司用最深的主色，可比公司用同色系较浅的色，既便于快速定位目标，又保持同一色系的克制。

### 图表背景与网格线

| 元素 | 样式 |
|---|---|
| 图表背景 | 透明（继承 figure 容器背景） |
| 网格线 | #f1f5f9，stroke-width 1px |
| 零线 | #94a3b8，stroke-width 1.2px |
| 坐标轴文字 | #94a3b8，font-size 11px |
| 数据标签 | #334155，font-size 12px，font-weight 600 |

### 柱状图样式

- 柱宽根据数据量自适应，最小 24px、最大 80px
- 柱顶圆角 `rx="4"`，仅纵向柱加，横向条与堆叠条不加（否则破坏首尾相接的视觉衔接）
- 涨跌柱分别用语义色，分类柱用主色板

### 折线图样式

- 线宽 2.5px，`stroke-linejoin: round`
- 数据点半径 4px，悬停放大至 6px
- 线条下方可填充同色 10% 透明度的渐变区域

### 文字规范

| 元素 | 字号 | 字重 | 颜色 |
|---|---|---|---|
| 图表标题 | 13px | 600 | #334155 |
| 坐标轴标签 | 11px | 400 | #94a3b8 |
| 数据标签 | 12px | 600 | #334155 |
| 图例文字 | 12px | 500 | #64748b |
| 注释文字 | 11px | 400 | #94a3b8 |

其他约定：

- 同一指标在不同图表中使用同一颜色，避免同类数据在两张图中颜色不同
- 数据来源与注释用浅灰小字，与正文区分
- 不使用立体效果；渐变仅用于柱状图柱体的深浅层次，不用于制造拟物感

## 标注要求

每个图表下方须有三行文字，缺一不可。

第一行，图表标题，说明它呈现什么关系，采用陈述句（如"2026 年上半年营收与净利同比：公司与可比公司对照"），不采用疑问句或"关于……的图"这类虚指结构。

第二行，数据来源，写明层级与文件名称（如"数据来源：各公司 2026 年半年度报告"）。

第三行，读图要点，用一到两句话说明该图支持什么判断。这一行是图表与分析之间的连接，缺了图表就只是装饰。

图表中的数值标注保留必要精度，正文取整。同比数据须标明正负号，负值以括号或减号明确表示。

## 结论卡与表格

核心结论以卡片形式呈现，每张卡一句判断，卡片左侧用色条标示判断性质：结构性风险用深绿，过渡期风险用灰蓝，阶段性困难用浅红。分层判断（如收入层面与利润层面结论不同）须用两张并列卡片，不得合并成一句。

观察点表格固定三列：观察点、看什么、说明什么。第三列须写明"恶化／改善"的判定方向，不能只有指标名称。

数据来源表须完整呈现来源规范的七个字段，按层级排序，一级在前。状态列用文字标注，不用符号代替。

## 技术实现

使用内联 SVG 绘制图表，不用外部图表库。内联 SVG 不依赖网络，脱离网络仍可正常显示与打印。

字体使用系统中文字体栈，避免依赖外部字体文件。数字采用等宽字体栈，便于纵向比对。

### 响应式

页面须适配窄屏。缺少响应式规则时，多列的数据来源表会溢出屏幕，手机端无法阅读。

须包含宽度小于 768 像素时的规则，处理四件事：表格改为可横向滚动、导航条可横向滚动、结论卡改为单列、正文字号下调一级。

### 打印

打印样式下导航条与交互元素隐藏，图表强制分页不断裂。

须设置页边距。页码应按下列方式处理：CSS 的页码计数器只在支持分页媒体的渲染引擎中生效，浏览器直接打印时不会产生页码。因此若交付物需要页码，须在页面或说明中提示使用浏览器的"页眉和页脚"打印选项，不得仅依靠样式表并在报告中宣称已含页码。

## SVG 图表的数据编码与坐标自检

手工编写 SVG 时最易出错的是两处：柱长与数值不成比例，以及文字坐标越界。两者都不会报错，只会让图表读错或标签被裁掉，因此须在成稿前逐项自检。

### 柱状图的编码规则

**正负须用方向编码。** 设一条标注为 0 的零线，正值自零线向上，负值自零线向下。仅用颜色区分正负是错误编码，因为读者会按柱长比较，而柱长与正负这一维度脱钩。

**柱长须与数值成比例。** 同一张图内所有柱共用同一比例尺，即像素高度除以数值所得比值必须一致。凭目测估高度是常见错误，会让数值大的柱子反而更短。

**比例尺的计算方法**：先看该图内的最大正值与最大绝对值负值，再量出零线上下各自可用的像素空间，取两个可用空间与对应最大值之比的较小者作为比例尺。这样可保证最长的柱子恰好放得下，且所有柱成比例。

**零线须标注。** 图上须出现"0"的刻度标识，读者才能判断柱子的方向含义。

**方向含义须写入图注。** 在读图要点中说明零线以上为增长、以下为下降。

### 文字坐标自检

所有文字元素的纵坐标须落在画布范围内，且不得与相邻文字重叠。

容易出错的是负值柱的数值标签：柱体向下延伸后，标签若仍按正值的写法放在柱顶上方，就会落在柱体内部或与零线重叠。负值柱的数值标签应放在柱底下方。

还须注意分组（`<g transform="translate(...)">`）的偏移量。文字坐标是相对于分组原点而非画布原点，判断是否越界时必须把偏移量加上，只读元素的 `y` 属性会得出错误结论。

**负值柱的矩形参数易写错。** 正值柱是 `y = 零线 − 高度`、`height = 高度`；负值柱应是 `y = 零线`、`height = 高度`。若把负值柱写成 `y = 零线 + 高度`，柱体就会整体下移一个自身高度，看起来像凭空多出一截。判断方法是看柱体靠近零线的那一侧是否贴住零线：正值贴底边，负值贴顶边。

**坐标轴刻度须与柱长共用同一比例尺。** 刻度线标注的是数值，其像素位置必须等于零线减去"数值×比例尺"。若两者各算各的，网格线就在骗人：读者按刻度读柱高会得到错误结论。这一项在手工改图后最容易失配。

**画布高度须一次留够。** 纵向空间应容纳最长柱、柱顶数值标签、零线、类目名行四者之和，并另留余量。事后发现不够而改画布高度时，所有与底部对齐的元素坐标都要跟着改，容易漏改。

**自检清单**：

- 同一张图内各柱的"像素高度÷数值"比值一致（逐柱验算，允许一位小数的舍入误差）
- 每根柱的像素高度不超过零线上下各自的可用空间
- 正值柱的底边、负值柱的顶边都贴住零线，偏差不超过 1 像素
- 坐标轴每个刻度的像素位置等于"零线 − 数值×比例尺"，误差不超过 6 像素
- 所有文字元素的坐标加上所属分组偏移量后，仍在画布范围内
- 数值标签与分类标签的纵向间距不小于 20 像素
- 最长的柱其数值标签与底部标签行之间仍有余量

上述各项靠目测都不可靠，尤其是刻度与柱长的比例是否一致、负值柱有没有贴住零线。写成脚本从文件中解析矩形参数与刻度文字再逐项验算，比人工核对稳当。

**脚本自检须避免写死期望值。** 若把"某根柱的值 9.41、像素高 31.9"抄进脚本比对，只能验证作者抄进来的数字与算出的比例一致，发现不了锚点错位与刻度失配，因为两者用的是同一套错误坐标。正确做法是从文件里解析出矩形参数、刻度文字与分组偏移量，再检查它们彼此是否自洽。

## 报告的交互元素

### 基本要求：渐进增强

交互元素用于降低阅读成本，不用于装饰。

**所有内容在关闭脚本时仍须完整可读**，交互只起增强作用。报告可能被打印或转为 PDF，那时交互不存在，因此不得有内容只能通过交互获得。

### 该加的四类

**结论卡展开依据。** 点击结论卡展开，显示支撑该判断的具体数据与来源。这项把"判断可追溯"落到了可操作的位置。用 `details` 与 `summary` 实现，无需脚本。

**数据来源表筛选。** 按来源层级或核实状态筛选，便于读者直接定位待核实项。用按钮组切换表格行的显示与隐藏。

**图表数值提示。** 在 SVG 的图形元素内嵌入 `title`，鼠标悬停显示精确数值。无需脚本。图表上标注取整值，精确值由悬停获得，两者不矛盾。

**图表口径切换。** 适用于同一组对象有多个可比指标的图，例如营收同比与净利同比。用按钮切换两组数据，避免并排成两张小图后各自都看不清。

### 不该加的

- 不加动画与自播放效果（关键帧、循环动画、滚动特效），打印时会产生错位。**悬停的轻量过渡不在此限**，卡片上浮、行背景变色这类反馈可用，但打印样式下须还原为静态，相关规则见 `report-template.md` 的打印段落
- 不加需要联网才能使用的功能
- 不加与结论无关的装饰性交互
- 不把交互当作内容组织手段，例如把关键内容默认折叠

### 技术要求

- 脚本内联，不使用外部库
- 优先选择零脚本方案，即 `details`／`summary` 与 `title`
- 交互控件须有文字标签，不用图标代替
- 打印样式下交互控件隐藏，被折叠的内容须展开呈现
- 筛选控件的初始状态为显示全部

### 自检

- 关闭脚本后，报告的全部内容仍可读取
- 打印预览中无折叠内容缺失
- 每个交互控件的效果在不看说明的情况下可预期

## 可访问性

- 每张图表的含义须在正文中有对应文字表述，图形不是唯一信息载体
- 颜色不得作为唯一区分手段，涨跌须同时用正负号、箭头或文字标注
- 表格首行与首列使用表头样式
- 正文与背景的对比度不低于 4.5:1

## SVG 生成硬规则

以下规则来自一次真实事故：示例报告中有 15 个 `<rect>` 标签漏写闭合标签，而交付自检脚本的配对检查列表里只有 HTML 标签、没有 SVG 标签，因此检查全过、错误上线的风险一直存在，直到有人逐张读源码才发现。

**SVG 是 XML 语法，不是 HTML 语法。** HTML 有隐式闭合规则（写 `<p>` 不写 `</p>` 也能正常渲染），SVG 没有。遗漏闭合标签会改变元素嵌套关系：未闭合的 `<rect>` 会把后面的元素收成自己的子元素，导致悬停提示失效、分组错位。浏览器容错处理下画面往往看不出异常，所以这类错误只能靠检查发现，不能靠看。

### 规则一：所有标签须显式闭合

`rect`、`circle`、`line`、`text`、`title`、`g`、`defs`、`linearGradient`、`stop` 等，凡有子元素或内容的都必须写出闭合标签。

```svg
<!-- 正确：有 title 子元素，须显式闭合 -->
<rect x="0" y="0" width="100" height="30" fill="#6366f1">
  <title>体外诊断 38.68%</title>
</rect>

<!-- 正确：无子元素时可用自闭合 -->
<line x1="0" y1="0" x2="580" y2="0" stroke="#f1f5f9" stroke-width="1"/>

<!-- 错误：有 title 却不闭合 rect -->
<rect x="0" y="0" width="100" height="30" fill="#6366f1">
  <title>体外诊断 38.68%</title>
```

**判据：只要标签内有 `<title>` 或其他子元素，就必须用显式闭合；自闭合只用于确实无内容的元素。**

### 规则二：圆角只加在纵向柱上

纵向柱顶部用 `rx="4"`。横向条形与堆叠条形不加，因为堆叠条各段首尾相接，圆角会在接缝处露出背景色，破坏连续感。

**判图的类型，不要按单个柱子判断。** 一张图里最窄的那根柱子可能宽小于高，按单柱判断会误加成纵向柱。判据是整张图的取值分布：标为数据条形的元素里，高度取值多而宽度取值单一的是纵向柱图，反之是横向条形图。

### 规则三：多层柱用同色系垂直渐变

纵向柱图的柱体用同色系上下渐变（深在上、浅在下），通过 `defs` 中的 `linearGradient` 定义，柱子的 `fill` 写 `url(#渐变id)`。横向条与堆叠条用纯色即可，堆叠条各段本就用不同深浅区分。

### 规则四：`defs` 须置于每个 SVG 内

**SVG 的 `defs` 作用域不跨 SVG 元素。** 同一页面有多张图时，每张图都要在自己的 `<svg>` 内写一份 `defs`，不能只写在第一张图里指望其他图引用到。

### 规则五：文字坐标不得越界

`<text>` 的 y 是**基线位置**，不是文字顶边，判断上边界时要减去约 0.8 倍字号。带 `text-anchor` 的文字要按实际对齐方向估算左右边界。所有坐标须加上所属分组的 `translate` 偏移量后再判断。

### 规则六：数据图形须含 `title`

每个表示数据的图形元素内嵌 `<title>`，供悬停显示精确值。格式为"名称 数值，说明"。图上标注取整值、悬停显示精确值，两者不矛盾。

### 规则七：配色一致

同一图内涨值统一用涨色、跌值统一用跌色；分类数据用同一色系的深浅，不混用色系。具体色值见本文的配色规则一节。

### 规则八：viewBox 尺寸统一

- 纵向柱状图与折线图：`viewBox="0 0 680 320"`
- 横向条形图：`viewBox="0 0 680 [高度]"`，高度按条数算，每条约 42px 加边距
- `width="100%"`，`height` 属性与 viewBox 高度一致

内容须在该尺寸内完整呈现，超出即被裁切。

### 用脚本改 SVG 时的一条陷阱

用正则批量修改 SVG 时，若替换函数只拼接了开标签与内容、忘了把闭合标签加回去，每匹配一次就会吃掉一个闭合标签。这类破坏不会报错，返回值也是"成功"，只有数一遍标签才看得出来。

**正则改 SVG 的写法要求**：匹配时把闭合标签纳入分组并显式写回，或用"只改开标签属性、不动内容"的写法。改完必须数一遍各标签的开闭数量。

## 柱状图骨架

纵向柱状图的骨架如下。方括号处填入实际数据，其余结构照用。

```svg
<svg viewBox="0 0 680 320" width="100%" height="320" role="img" aria-label="[图的含义]">
  <defs>
    <linearGradient id="bar-up" x1="0" y1="0" x2="0" y2="1">
      <stop offset="0%" stop-color="#6366f1"/>
      <stop offset="100%" stop-color="#a5b4fc"/>
    </linearGradient>
    <linearGradient id="bar-down" x1="0" y1="0" x2="0" y2="1">
      <stop offset="0%" stop-color="#22c55e"/>
      <stop offset="100%" stop-color="#86efac"/>
    </linearGradient>
  </defs>

  <text x="0" y="18" font-size="13" font-weight="600" fill="#334155">[图表标题]</text>

  <g transform="translate(50,44)">
    <line x1="0" y1="[刻度线Y]" x2="580" y2="[刻度线Y]" stroke="#f1f5f9" stroke-width="1"/>
    <line x1="0" y1="[零线Y]" x2="580" y2="[零线Y]" stroke="#94a3b8" stroke-width="1.2"/>
    <text x="-8" y="[刻度线Y+4]" text-anchor="end" font-size="11" fill="#94a3b8">[刻度值]</text>

    <rect x="[X]" y="[Y]" width="[W]" height="[H]" rx="4" fill="url(#bar-up)">
      <title>[名称] [数值]，[说明]</title>
    </rect>
    <text x="[X+W/2]" y="[Y-8]" text-anchor="middle" font-size="12" font-weight="600" fill="#334155">[标签]</text>
    <text x="[X+W/2]" y="[底部Y+16]" text-anchor="middle" font-size="12" fill="#64748b">[类目名]</text>
  </g>

  <g transform="translate(0,[注释Y])" font-size="11.5" fill="#94a3b8">
    <text x="0" y="0">[读图要点]</text>
  </g>
</svg>
```

使用要点：每根柱须锚定零线（正值柱底边贴零线，负值柱顶边贴零线）；柱长与数值成比例，同图共用一个比例尺；轴刻度位置等于"零线减数值乘比例尺"，与柱长用同一比例尺。以上三项须逐项验算，方法与自检清单见本文的编码自检一节。
