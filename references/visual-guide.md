# 可视化规范

研报交付形态为单文件 HTML 页面，其中须含四至七张图表。规范规定页面结构、图表类型与数据的映射规则、配色与标注要求。

## 页面结构

单文件 HTML，所有样式与脚本内联，不依赖外部资源，双击即可在浏览器中打开。页面自上而下分五个区块。

| 区块 | 内容 | 图表 |
|---|---|---|
| 报告头 | 公司名称、股票代码、报告日期、数据截止期、分析框架 | 无 |
| 核心结论 | 三到五句判断，以结论卡形式呈现，分层判断用两块并列 | 可选一张估值或经营概览图 |
| 分节正文 | 按研报模板的各章节展开，每节承载其核心图表 | 四至七张 |
| 观察点 | 该盯什么、不该盯什么，表格形式 | 可含一张趋势图 |
| 数据来源 | 来源追溯表，含层级、来源名称、日期、定位、状态 | 无 |

页面顶部设固定导航条，点击跳转至各节。页面宽度控制在 1100 像素以内的居中栏，正文行高不低于 1.7，确保长文可读。

## 图表数量与类型映射

正文须含四至七张图表，覆盖下列核心判断。图表类型按数据关系选定，不按美观偏好选定。

| 数据关系 | 图表类型 | 用于呈现 |
|---|---|---|
| 收入的构成与占比 | 环形图或堆叠条形图 | 各业务板块占比、境内外收入结构 |
| 变化的方向与幅度 | 分组柱状图 | 营收与净利的同比，公司自身跨期对照 |
| 同业同期的横向比较 | 分组柱状图或斜率图 | 公司与可比公司的营收、净利同比对照 |
| 时间序列的趋势 | 折线图 | 毛利率、净利率、汇兑损益的逐期变化 |
| 结构差异与缺口 | 瀑布图或对照条形图 | 主业缺口的绝对金额与新业务体量的对比 |
| 多指标的相对位置 | 雷达图或热力表 | 公司与同业在盈利能力、成长性、现金流上的分布 |
| 目标与现状的距离 | 进度条形图 | 市占率目标与当前水平的差距 |

**硬性要求**：

- 同业对照须单独成图，不得只在文字中表述。这是全文归因的基础，图形化后差异一目了然。
- 至少有一张图呈现时间序列，用于说明趋势而非单点。
- 至少有一张图呈现公司与同业的并列，用于区分行业性问题与个体问题。
- 饼图仅用于部分与整体的关系，且分块不超过五块。
- **图表总数不少于四张，不多于七张（含）。**

上限的理由是取舍。四张对应四类核心判断，加行业环境一张为五张，剩余两张用于估值、目标进度或同业多指标分布这类可选内容。**同一结论不得重复作图**，例如同一组数据既画柱状图又画折线图属于凑数。超过七张说明制图时未作取舍，读者的注意力会被摊薄，重点图反而失去分量。

## 配色规则

页面采用浅色底、深色字，保证打印与投影均可读。

涨跌配色遵循 A 股惯例：

- 上升、改善、增长：红色系（#c0392b 或 #d64541）
- 下降、恶化、下滑：绿色系（#1e8449 或 #27ae60）
- 中性、同比持平、无方向数据：灰蓝色系（#5d6d7e）

配色方案相反的情形（如欧美市场惯例的红跌绿涨）不适用于本技能。所有图表与表格中的涨跌标注须保持一致。

其他约定：

- 同一指标在不同图表中使用同一颜色，避免同类数据在两张图中颜色不同
- 同业对照图中，目标公司用饱和色，可比公司用低饱和色，以便快速定位
- 数据来源与注释用浅灰小字，与正文区分
- 不使用渐变、阴影、立体效果

## 标注要求

每个图表下方须有三行文字，缺一不可。

第一行，图表标题，说明它呈现什么关系，采用陈述句（如"2026 年上半年营收与净利同比：公司与可比公司对照"），不采用疑问句或"关于……的图"这类虚指结构。

第二行，数据来源，写明层级与文件名称（如"数据来源：各公司 2026 年半年度报告"）。

第三行，读图要点，用一到两句话说明该图支持什么判断。这一行是图表与分析之间的连接，缺了图表就只是装饰。

图表中的数值标注保留必要精度，正文取整。同比数据须标明正负号，负值以括号或减号明确表示。

## 结论卡与表格

核心结论以卡片形式呈现，每张卡一句判断，卡片左侧用色条标示判断性质：结构性风险用深绿，过渡期风险用灰蓝，阶段性困难用浅红。分层判断（如收入层面与利润层面结论不同）须用两张并列卡片，不得合并成一句。

观察点表格固定三列：观察点、看什么、说明什么。第三列须写明"恶化／改善"的判定方向，不能只有指标名称。

数据来源表须完整呈现来源规范的七个字段，按层级排序，一级在前。状态列用文字标注，不用符号代替。

## 技术实现

使用内联 SVG 绘制图表，不用外部图表库。内联 SVG 不依赖网络，脱离网络仍可正常显示与打印。

字体使用系统中文字体栈，避免依赖外部字体文件。数字采用等宽字体栈，便于纵向比对。

### 响应式

页面须适配窄屏。缺少响应式规则时，多列的数据来源表会溢出屏幕，手机端无法阅读。

须包含宽度小于 768 像素时的规则，处理四件事：表格改为可横向滚动、导航条可横向滚动、结论卡改为单列、正文字号下调一级。

### 打印

打印样式下导航条与交互元素隐藏，图表强制分页不断裂。

须设置页边距。页码应按下列方式处理：CSS 的页码计数器只在支持分页媒体的渲染引擎中生效，浏览器直接打印时不会产生页码。因此若交付物需要页码，须在页面或说明中提示使用浏览器的"页眉和页脚"打印选项，不得仅依靠样式表并在报告中宣称已含页码。

## SVG 图表的数据编码与坐标自检

手工编写 SVG 时最易出错的是两处：柱长与数值不成比例，以及文字坐标越界。两者都不会报错，只会让图表读错或标签被裁掉，因此须在成稿前逐项自检。

### 柱状图的编码规则

**正负须用方向编码。** 设一条标注为 0 的零线，正值自零线向上，负值自零线向下。仅用颜色区分正负是错误编码，因为读者会按柱长比较，而柱长与正负这一维度脱钩。

**柱长须与数值成比例。** 同一张图内所有柱共用同一比例尺，即像素高度除以数值所得比值必须一致。凭目测估高度是常见错误，会让数值大的柱子反而更短。

**比例尺的计算方法**：先看该图内的最大正值与最大绝对值负值，再量出零线上下各自可用的像素空间，取两个可用空间与对应最大值之比的较小者作为比例尺。这样可保证最长的柱子恰好放得下，且所有柱成比例。

**零线须标注。** 图上须出现"0"的刻度标识，读者才能判断柱子的方向含义。

**方向含义须写入图注。** 在读图要点中说明零线以上为增长、以下为下降。

### 文字坐标自检

所有文字元素的纵坐标须落在画布范围内，且不得与相邻文字重叠。

容易出错的是负值柱的数值标签：柱体向下延伸后，标签若仍按正值的写法放在柱顶上方，就会落在柱体内部或与零线重叠。负值柱的数值标签应放在柱底下方。

还须注意分组（`<g transform="translate(...)">`）的偏移量。文字坐标是相对于分组原点而非画布原点，判断是否越界时必须把偏移量加上，只读元素的 `y` 属性会得出错误结论。

**负值柱的矩形参数易写错。** 正值柱是 `y = 零线 − 高度`、`height = 高度`；负值柱应是 `y = 零线`、`height = 高度`。若把负值柱写成 `y = 零线 + 高度`，柱体就会整体下移一个自身高度，看起来像凭空多出一截。判断方法是看柱体靠近零线的那一侧是否贴住零线：正值贴底边，负值贴顶边。

**坐标轴刻度须与柱长共用同一比例尺。** 刻度线标注的是数值，其像素位置必须等于零线减去"数值×比例尺"。若两者各算各的，网格线就在骗人：读者按刻度读柱高会得到错误结论。这一项在手工改图后最容易失配。

**画布高度须一次留够。** 纵向空间应容纳最长柱、柱顶数值标签、零线、类目名行四者之和，并另留余量。事后发现不够而改画布高度时，所有与底部对齐的元素坐标都要跟着改，容易漏改。

**自检清单**：

- 同一张图内各柱的"像素高度÷数值"比值一致（逐柱验算，允许一位小数的舍入误差）
- 每根柱的像素高度不超过零线上下各自的可用空间
- 正值柱的底边、负值柱的顶边都贴住零线，偏差不超过 1 像素
- 坐标轴每个刻度的像素位置等于"零线 − 数值×比例尺"，误差不超过 6 像素
- 所有文字元素的坐标加上所属分组偏移量后，仍在画布范围内
- 数值标签与分类标签的纵向间距不小于 20 像素
- 最长的柱其数值标签与底部标签行之间仍有余量

上述各项靠目测都不可靠，尤其是刻度与柱长的比例是否一致、负值柱有没有贴住零线。写成脚本从文件中解析矩形参数与刻度文字再逐项验算，比人工核对稳当。

**脚本自检须避免写死期望值。** 若把"某根柱的值 9.41、像素高 31.9"抄进脚本比对，只能验证作者抄进来的数字与算出的比例一致，发现不了锚点错位与刻度失配，因为两者用的是同一套错误坐标。正确做法是从文件里解析出矩形参数、刻度文字与分组偏移量，再检查它们彼此是否自洽。

## 报告的交互元素

### 基本要求：渐进增强

交互元素用于降低阅读成本，不用于装饰。

**所有内容在关闭脚本时仍须完整可读**，交互只起增强作用。报告可能被打印或转为 PDF，那时交互不存在，因此不得有内容只能通过交互获得。

### 该加的四类

**结论卡展开依据。** 点击结论卡展开，显示支撑该判断的具体数据与来源。这项把"判断可追溯"落到了可操作的位置。用 `details` 与 `summary` 实现，无需脚本。

**数据来源表筛选。** 按来源层级或核实状态筛选，便于读者直接定位待核实项。用按钮组切换表格行的显示与隐藏。

**图表数值提示。** 在 SVG 的图形元素内嵌入 `title`，鼠标悬停显示精确数值。无需脚本。图表上标注取整值，精确值由悬停获得，两者不矛盾。

**图表口径切换。** 适用于同一组对象有多个可比指标的图，例如营收同比与净利同比。用按钮切换两组数据，避免并排成两张小图后各自都看不清。

### 不该加的

- 不加动画与过渡效果，打印时会产生错位
- 不加需要联网才能使用的功能
- 不加与结论无关的装饰性交互
- 不把交互当作内容组织手段，例如把关键内容默认折叠

### 技术要求

- 脚本内联，不使用外部库
- 优先选择零脚本方案，即 `details`／`summary` 与 `title`
- 交互控件须有文字标签，不用图标代替
- 打印样式下交互控件隐藏，被折叠的内容须展开呈现
- 筛选控件的初始状态为显示全部

### 自检

- 关闭脚本后，报告的全部内容仍可读取
- 打印预览中无折叠内容缺失
- 每个交互控件的效果在不看说明的情况下可预期

## 可访问性

- 每张图表的含义须在正文中有对应文字表述，图形不是唯一信息载体
- 颜色不得作为唯一区分手段，涨跌须同时用正负号、箭头或文字标注
- 表格首行与首列使用表头样式
- 正文与背景的对比度不低于 4.5:1
