# 回溯验证规范

## 目的

回溯验证用于检验本技能产出的判断是否经得起时间检验。通过对比当初的判断与后续的实际结果，识别方法论的系统性偏差，持续校准判断标准。

本技能中的量化阈值（可转换性判断的三个阈值、财务异常信号的判定线、各行业模块内的阈值）均为未经实证校准的参考起点，其校准依赖本规范积累的偏差数据。**没有回溯验证，那些阈值就只是未经检验的猜测。**

## 何时触发

- 每次执行跨报告期跟踪时，同步执行回溯验证
- 用户主动要求对历史报告做回溯时
- 新一报告期数据发布后，对上一次判断做验证

## 验证框架

### 第一步：提取历史判断

从上一次报告或跟踪记录中提取：

| 提取项 | 说明 |
|---|---|
| 核心结论 | 结构性风险、过渡期风险、阶段性困难 |
| 判断依据 | 支撑结论的关键数据与逻辑链 |
| 观察点 | 当时设定的三到四个验证指标及其判定方向 |
| 情景假设 | 若有情景分析，提取基准、乐观、悲观三档假设 |
| 量化取值 | 若用了量化阈值，提取当时的替代补缺率、补缺所需年数、资本支出强度及其结论档 |

提取须原样照录，不得按当前认知修饰。修饰过的历史判断无法用于校准。

### 第二步：收集新证据

获取新一报告期的实际数据，逐项与历史判断对比：

| 对比项 | 方法 |
|---|---|
| 观察点变化 | 逐一记录各观察点的实际值与变化方向，与当初设定的判定方向对比 |
| 核心数据变化 | 营收、利润、现金流等核心指标的实际趋势与当初预判对比 |
| 外部环境变化 | 当初识别的风险端口是否实际发生，幅度是否落在情景区间内 |
| 量化阈值的有效性 | 当时的结论档与后续实际走势是否一致 |

### 第三步：判定偏差

| 偏差类型 | 定义 | 处理方式 |
|---|---|---|
| 判断正确 | 实际结果与判断方向一致 | 维持方法论不变 |
| 方向正确但幅度偏差 | 判断为过渡期风险且确实处于过渡期，但恢复速度慢于预期 | 检查阈值是否需要调整，如补缺所需年数的分档 |
| 方向错误 | 判断为阶段性困难但实际恶化为结构性问题 | 回溯分析失误环节：数据问题、方法问题，还是不可预见的外部冲击 |
| 意外事件 | 发生分析时无法预见的重大事件 | 记录为不可抗力，不修改方法论，但可在情景分析中增加该类事件的覆盖 |

**判定须落到具体环节。** 只记"判断错误"不足以校准，须定位是哪一步出的错：第一步收入来源识别、第二步风险敞口判断，还是第三步可转换性判断。定位不到环节的偏差无法用于改进。

### 第四步：产出回溯说明

回溯说明为独立文档，不修改原始报告。原始报告保留当时的判断，历史判断被事后修改会让校准失去基准。

```markdown
# 回溯验证：［公司名称］［报告期］

## 原始判断
［上次的核心结论与关键依据，原样照录］

## 新报告期数据
［关键数据的实际值与同比］

## 观察点验证
| 观察点 | 原始判定方向 | 实际变化 | 偏差类型 |
|---|---|---|---|

## 判断修正
［是否需要修正原始判断，修正依据是什么］

## 方法论反思
［本次验证对方法论的启示，是否需要调整阈值或规则］
```

## 偏差的统计与汇总

跨多次回溯验证后定期统计偏差分布：

- 判断正确的比例（目标高于 70%）
- 最常见的偏差类型（方向错误还是幅度偏差）
- 偏差集中在哪一步（第一步、第二步、第三步）

统计数据用于校准方法论。若某一步的偏差率持续偏高，应检查该步的判断标准是否存在系统性问题，而非只调整单个阈值。

统计结果同时用于更新各阈值的校准状态。阈值被调整时须在更新日志中写明：调整了哪个阈值、依据多少次回溯、偏差分布如何。这样阈值的演进过程可追溯。

## 与分行业模块的关系

行业补充模块中的阈值同样适用本规范。`industry-addons/` 下标注为"尚未经真实案例验证"的模块，须在积累该行业的回溯数据后再转为基础较牢的模块。校准状态写在该模块文件开头的成熟度标注中。
